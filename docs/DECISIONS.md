## D-002：第一版不开发内核驱动

- 日期：2026-08-19
- 状态：已确认
- 决策：优先复用 Windows 自带 BLE HID 驱动，在用户态使用 Raw Input 捕获遥控器事件。
- 理由：实测设备已经被 Windows 识别为标准 BLE HID Keyboard；用户态应用安装更简单、风险更低，也更适合第一次开源发布。
- 影响：“驱动”在产品表达中指常驻配套应用，而不是 `.sys` 内核驱动。只有证据表明系统 HID 层无法满足需求时才重新评估。

## D-003：麦克风与按键分两条路线

- 日期：2026-08-19
- 状态：已确认
- 决策：按键映射作为 v0.1 主线；麦克风作为自定义 BLE GATT 协议研究线。
- 理由：系统已暴露标准 HID 按键接口，但没有发现普通 Windows 音频输入端点，并存在多个厂商自定义 GATT 服务。
- 影响：麦克风逆向失败或延期不阻塞按键版发布。
- 后续状态：产品优先级已被 D-009 更新；该条仍适用于“按键核心可以独立开发”，但遥控器麦克风不再只是可有可无的实验能力。

## D-009：遥控器麦克风是核心使用需求

- 日期：2026-08-20
- 状态：需求已确认，桥接方案待决定。
- 决策：点击麦克风实体键时，不仅触发 Typeless 的语音输入快捷键，还要启动小米遥控器自身的麦克风采集，并让 Typeless 能够接收到该人声。
- 理由：用户当前电脑的系统麦克风已经损坏，单独触发 Typeless 快捷键不能完成语音输入。
- 技术影响：
  - 先通过 ATVV 的能力协商、`MIC_OPEN`/`MIC_CLOSE` 和音频通知获取并解码遥控器音频。
  - 解码后的 PCM 还必须进入 Windows 可枚举的录音端点，Typeless 才能将其作为麦克风使用。
  - 微软官方架构将虚拟录音端点归入音频驱动；纯用户态 GATT 解码不能独自创建一个可供任意第三方应用选择的系统麦克风。
  - 需要决定原型是否接受成熟的已签名虚拟音频桥，或进入自研虚拟音频驱动路线。

## D-010：原型允许使用现成虚拟音频桥

- 日期：2026-08-20
- 状态：已确认，具体产品待选择。
- 用户选择：1（成熟、已签名的虚拟音频桥）。
- 决策：原型阶段不自研虚拟麦克风驱动；MiVibe 保持用户态，通过现成的 Windows 虚拟音频线把解码后的 PCM 提供给 Typeless。
- 理由：先用最短路径验证“遥控器采音 → ATVV 解码 → Windows 录音端点 → Typeless”的完整链路，再根据开源发布需求评估长期方案。
- 本机检查：没有发现可直接复用的虚拟音频线；NVIDIA Virtual Audio 不是本场景需要的播放到录音桥。
- 发布约束：第三方驱动不是 MiVibe 源码的一部分；其安装、许可、来源和卸载方式必须单独说明，未经确认不静默安装或捆绑发布。

## D-011：原型采用 VB-CABLE

- 日期：2026-08-20
- 状态：已确认并已安装验证。
- 用户选择：1（VB-CABLE）。
- 决策：原型把解码后的遥控器 PCM 播放到 VB-CABLE 的播放端，并让 Typeless 从对应录音端读取。
- 理由：VB-CABLE 只提供本项目需要的播放到录音桥，配置和运行负担低于完整虚拟混音器。
- 安装边界：
  - 只从 VB-Audio 官方渠道获取。
  - 安装需要管理员权限和重启，必须由用户明确批准并在适当阶段单独执行。
  - 初期仓库只记录依赖和安装指引，不提交或重新包装 VB-CABLE 二进制。
  - README 必须说明其 donationware 许可和第三方归属。
- 本机验证：`CABLE Input` 与 `CABLE Output` 均已注册且为 Active；当前无需重启。MiVibe 只使用标准立体声/共享模式播放端，不使用额外的 `CABLE In 16ch` 端点。

## D-012：遥控器开麦失败不阻止 Typeless

- 日期：2026-08-20
- 状态：已确认。
- 用户选择：3。
- 决策：点击麦克风实体键时始终触发 Typeless；若遥控器麦克风或音频桥失败，MiVibe 显示明确错误，但不取消 Typeless 快捷键。
- 理由：保留 Typeless 自身使用其他录音设备的兜底能力，避免蓝牙故障导致语音入口完全不可用。

## D-013：默认使用温和的软件增益

- 日期：2026-08-20
- 状态：已确认默认值，可在后续 UI 调整。
- 决策：解码后 PCM 默认增加 `+6 dB`，并做 16-bit 限幅保护；原始 ADPCM 保持不变。
- 理由：首段录音人声清楚、语速正常且无杂音，但用户听感略小；测得整体 RMS 约 `-38.07 dBFS`。
- 影响：命令行提供 `--gain-db`，允许范围为 `-12` 到 `+24 dB`；实时 VB-CABLE 输出复用同一参数。

## D-014：采用最小虚拟 HID 驱动，并规划正式微软签名

- 日期：2026-08-20
- 状态：已确认（首发系统范围与发布渠道仍待逐项确认）。
- 用户选择：1（虚拟 HID 路线），并明确要求在公开发布前规划正式驱动签名。
- 决策：新增一个范围尽可能小的 Windows KMDF 虚拟 HID 键盘驱动，让 Typeless 把右 `Ctrl + 右 Shift` 识别为硬件键盘输入；BLE、ATVV、音频解码、VB-CABLE 输出、按键状态机和配置仍保留在用户态服务中。
- 架构边界：
  - 内核驱动只负责接收受限的本地控制请求并提交预定义 HID 键盘报告，不连接网络，不解析蓝牙协议，不保存用户内容，也不调用 Typeless 私有 IPC。
  - 用户态服务负责识别小米遥控器、关联物理麦克风键状态、限流与故障恢复；驱动不能成为任意进程注入任意按键的通用接口。
  - 从第一版开始按 HVCI/内存完整性兼容要求设计和测试；不得把关闭 Windows 安全功能作为公开安装步骤。
- 签名与发布原则：
  - 本地开发包只能使用隔离的测试证书，严禁把私钥、测试证书口令或仅测试签名的驱动放入 GitHub Release。
  - 正式公开包通过 Microsoft Hardware Developer Program / Partner Center 提交并取得微软签名；账号、EV 代码签名证书、HLK/WHCP 测试矩阵与发布身份成本列入发布里程碑。
  - 稳定公开版优先按 HLK/WHCP 路线验证；是否用 attestation signing 做早期测试包，须在确认目标 Windows 版本和分发渠道后再决定。
  - GitHub Release 只发布可追溯的源码、构建说明、哈希、支持矩阵、安装/卸载与回滚说明，以及完成正式签名的驱动包或安装器。
- 取代关系：本决策取代 D-005 中“驱动不进入 v0.1 关键路径、不安装 WDK”的旧边界；D-005 对已探明按键与设备识别事实仍然有效。

## D-017：优先验证全局 F5 → F13 扫描码映射

- 日期：2026-08-20
- 状态：实验失败；当前映射等待替换或撤销。
- 用户选择：1（全局将 F5 映射为 F13）。
- 决策：在继续虚拟 HID/WDK/签名工程之前，先用 Windows 系统级 `Scancode Map` 把原始 F5 扫描码 `0x3F` 映射为 F13 `0x64`，并将 F13 添加为 Typeless 的第二套语音输入快捷键。
- 用户已知代价：该映射不能区分设备，电脑实体键盘 F5 也会变成 F13；启用和撤销都需要重启。
- 保护措施：
  - 启用前确认系统没有既有 `Scancode Map`。
  - 工具拒绝覆盖任何不完全匹配的现有映射。
  - 撤销工具只删除本项目写入的精确字节序列。
  - 保留 Typeless 原有右 `Ctrl + 右 Shift` 作为兜底快捷键。
- 架构影响：D-014 至 D-016 暂停执行，但不删除。如果重启后的 Typeless 实体键识别和端到端语音测试成功，虚拟 HID 驱动与正式签名从 v0.1 移到未来可选高级方案；若失败，立即撤销映射并恢复 D-014 路线。
- 当前系统状态：`Scancode Map` 仍为 `F5 (0x3F) → F13 (0x64)`。Windows 重启后，Typeless 不仅没有识别遥控器麦克风键，在同一个录入框中按电脑实体 F5 也完全没有反应；因此 F13 不能作为当前 Typeless Windows 版本的有效快捷键目标。
- 后续：先用电脑实体小键盘预检 Typeless 是否接受稳定的 Numpad 键；若接受，经过用户确认后把映射目标改成该键；若不接受，撤销当前映射并恢复 D-014 路线。

## D-018：将映射目标改为 Numpad Divide

- 日期：2026-08-20
- 状态：键位识别成功，但端到端一键按住交互失败。
- 用户决定：Typeless 可以识别 Numpad 系列键；选择 `Numpad Divide`，因为乘号使用频率更高。
- 决策：把全局扫描码映射从失败的 `F5 → F13` 迁移为 `F5 (0x003F) → Numpad Divide (0xE035)`。
- 理由：Numpad Divide 已通过 Typeless 实体键预检，不受 NumLock 状态影响，默认系统行为和日常输入频率低于 PrtSc、数字键和 Numpad Multiply。
- 迁移保护：工具只允许在“没有映射”或“精确等于本项目失败的 F13 映射”时写入；不覆盖任何其他值。撤销工具同时认识这两种项目管理值。
- 成功标准：重启后遥控器麦克风键能被 Typeless 识别为 Numpad Divide、可启动/停止语音输入，且 VB-CABLE 端到端转写成功。
- 当前状态：注册表已从精确的旧 F13 实验值迁移为 `00000000000000000200000035E03F0000000000`；管理员脚本退出码和状态脚本均为 0，尚待重启生效。
- 重启后结果：Typeless 成功把遥控器麦克风键保存为独立快捷键 `NumpadDivide`；原右 `Ctrl + 右 Shift` 组合仍保留为第二套兜底入口。键盘层轻量方案通过，不再需要为 v0.1 启动虚拟 HID 实施。
- 端到端修正：NumpadDivide 只解决按键识别，不能解决手势时序。Typeless 要求轻触切换录音，长按显示快捷键帮助；遥控器固件则只在实体麦克风键保持按下时发送音频。因此该方案不能独自实现原需求中的“一键按住说话”。是否恢复虚拟 HID 取决于下一项产品取舍。

## D-029：60 秒自动分段衔接延期，当前采用自然多段输入

- 日期：2026-08-21
